# Research Paper Agents

A supervisor-style multi-agent pipeline (LangGraph) that turns an assignment into a cited
research paper, run as a queued, resumable service.

```
assignment → analyst → topic ▸ human gate → scout (OpenAlex/Semantic Scholar + Crossref check)
           → thesis ▸ human gate → planner → writer → critic ⟲ (max 3 rounds) → paper
```

## Guarantees the code enforces

- **Citations are verified.** A source is kept only if its DOI resolves in Crossref and the title
  and year match. The writer can only cite `[S#]` ids that exist and are verified; the reference
  list is generated by code, not by the model.
- **Runs survive crashes and deploys.** Progress is checkpointed in Postgres after every node.
  A worker that dies mid-run is detected by a missed heartbeat, and the run resumes from its last
  checkpoint on another worker. Approval gates hold no worker while waiting.
- **Runs fail closed.** Token budget per run, at most `MAX_REVISIONS` critic rounds, a cap on
  active runs, and an API that refuses everything until `API_TOKEN` is set.
- **Untrusted text stays data.** Fetched papers and the assignment are passed to models inside
  delimiters with an instruction never to follow directions found in them.

## Run locally

```bash
uv venv --python 3.12 && uv pip install -e ".[dev]"
ruff check . && pytest -q          # Postgres tests need the container below, else they skip
docker run -d --rm --name rpa-test-pg -e POSTGRES_USER=research -e POSTGRES_PASSWORD=research \
  -e POSTGRES_DB=research -p 55432:5432 postgres:16-alpine
```

## Deploy (one VM)

```bash
cp .env.example .env               # set GROQ_API_KEY, POSTGRES_PASSWORD, API_TOKEN, DOMAIN
docker compose up -d --build       # db, api, worker, caddy (automatic HTTPS for $DOMAIN)
```

Open only ports 80 and 443. Point the domain's DNS at the VM before first start.

## API (Bearer `API_TOKEN`)

| Call | Purpose |
|---|---|
| `POST /runs {"prompt": "..."}` | Start a run (202) |
| `GET /runs/{id}` | Status; `gate` holds what the human is being asked |
| `POST /runs/{id}/approve {"approved": true}` | Answer a gate. Reject with `{"approved": false, "feedback": "..."}`; optional `topic` / `thesis` edits |
| `POST /runs/{id}/retry` | Re-queue a failed run; it resumes from its checkpoint |
| `POST /runs/{id}/cancel` | Cancel an active run |
| `GET /runs/{id}/draft` | Finished paper as Markdown |
| `GET /health` | Liveness and database check (no auth) |

Statuses: `queued → running → awaiting_approval → queued → … → completed | failed | cancelled`.
A `completed` run with `needs_human_review: true` hit the revision cap. `open_issues` lists what is
still wrong, and `note` says if the returned draft is an earlier version: on the cap the pipeline
returns the last draft that met every mechanical check (length, sections, verified citations)
rather than whatever the final rewrite produced.

## Operations runbook

| Situation | Action |
|---|---|
| Logs | `docker compose logs -f worker api` |
| Run failed | `GET /runs/{id}` shows `error`; fix the cause, then `POST /runs/{id}/retry` |
| Deploy | `docker compose up -d --build`. The worker gets 120s to finish its node on SIGTERM; anything cut off resumes |
| Backup | Cron `15 3 * * * cd /path/to/repo && BACKUP_REMOTE=r2:bucket ./scripts/backup.sh` |
| Restore | `docker compose stop worker api && ./scripts/restore.sh backups/<file>.sql.gz && docker compose up -d` |
| Bad LLM key | Auth errors are not retried; the run fails immediately with the provider's message |

Restore was drilled end to end (backup, drop all tables, restore, rows and checkpoints back).
Repeat the drill after any schema change.

## Known limits (from live runs against Groq)

- **Word limits are approximate.** The model overshoots per-section targets by up to about 35%.
  The pipeline measures real length on the rendered text, rescales, and rewrites, and it usually
  lands in range within 2 to 3 drafts, but not always. Expect some runs to end `needs_human_review`.
- **Free-tier token caps shape the design.** Groq's on-demand tier allows 8,000 tokens per minute for
  `gpt-oss-120b`, counted per request. Prompts are therefore bounded: at most `MAX_SOURCES` (15) ranked
  sources, abstracts truncated, and the critic sees only the body and the sources it cites. A paid tier
  removes this pressure.
- **Claim-level accuracy is only partly checked.** Sources are verified to exist; whether each sentence
  is faithfully supported by its source is judged by the LLM critic, which is not proof. The writer is
  told not to state statistics absent from the abstracts, and the critic flags unsupported ones.
- **Only abstracts are used**, not full text, so arguments are grounded in abstract-level evidence.
- **Only APA formatting is implemented** for in-text citations and references.
- One VM is a single point of failure; recovery is restore plus `docker compose up`.
- No live progress stream yet: clients poll `GET /runs/{id}`.
- Schema is one idempotent SQL file, not migrations. Add Alembic before the first breaking change.
- No golden-set eval yet. Build one and gate deploys on it before trusting quality changes.
